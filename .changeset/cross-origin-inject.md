Sprites on a CDN on another origin, opt-in (ADR-0027). Set `"crossOrigin": "inject"` with an `https://` `publicPath` (or build with `--cross-origin inject`; `svgworm init --cdn-url <url>` writes both). The build adds `icons.loader.<hash>.js`, a ~1.8 KB script that fetches the sprite with CORS and its integrity hash, parses it inertly, keeps only SVG-namespace content with no scripts, links or external URLs, and injects it once, so `<use href="#id">` works across origins. Icons need JavaScript in this mode and the CDN must send CORS headers; proxying `/icons/*` through your site stays the zero-JS option. Default builds are byte-identical to before.

**Breaking (inject mode only):** the manifest becomes `version: 2` with `crossOrigin`, the sprite's `integrity` and a `loader` entry. It needs `@svgworm/react` 0.3, and an `Icon.astro` generated by an earlier `svgworm init` must be written again (delete it and run `svgworm init`) or edited to accept version 2. The JSON Schema gains `crossOrigin`, and svgworm now also removes stale `icons.loader.<hash>.js` files in `outDir`.
