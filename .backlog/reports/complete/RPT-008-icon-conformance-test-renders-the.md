## Summary

`apps/site/tests/icon-conformance.test.ts` compares `createIcon` with `apps/site/src/components/Icon.astro`, which was generated by an older `svgworm init`: it reads manifest version 1 only, with no crossOrigin inject path. The template `init` writes today (`packages/svgworm/src/cli/init/plan.ts`) is checked only by string matches in `plan.test.ts`. The icon docs say "a test in this repository keeps them in step", which is only partly true.

## Where found

While fixing RPT-006 (TSK-094) on 2026-10-16. The current template was checked by hand: it was generated in a scratch Astro project and grepped.

## Evidence

`diff` between the generated `src/components/Icon.astro` and `apps/site/src/components/Icon.astro` shows the version check (`!== 1 && !== 2` vs `!== 1`) and the v2 `#id` sprite path missing from the site copy.

## Impact

A regression in the current template's markup (for example the `viewBox` size rule of ADR-0030, or inject handling) would pass CI. Fix: render the template from `plan.ts` in the conformance test, or regenerate the site's `Icon.astro` and add a check that it matches the template.
