# svgworm

## 0.3.0

### Minor Changes

- a31712e: New `name/case-folded` warning (ADR-0021). A file or folder name with a lowercase letter followed by an uppercase one, such as Figma's `ArrowLeft.svg`, still becomes `arrowleft`: letter case is never split, because git and case-insensitive file systems do not keep case-only renames. The build now says so and suggests the file name that gives a readable name (`arrow-left.svg`). A camelCase folder gets one warning for the folder, however many icons it holds. Names and output do not change; `--json` lists the warning in `warnings`.
- 45c33b1: `svgworm check --json` and the `CheckOutcome` type now expose the list of files a build would write or remove as `differences`. The old name, `stale`, held entries whose own status could be `missing`, `changed` or `stale`, which was confusing. `stale` stays as a deprecated alias with the same contents for one minor and is then removed.
- 5ba1d5c: Sprites on a CDN on another origin, opt-in (ADR-0027). Set `"crossOrigin": "inject"` with an `https://` `publicPath` (or build with `--cross-origin inject`; `svgworm init --cdn-url <url>` writes both). The build adds `icons.loader.<hash>.js`, a ~1.8 KB script that fetches the sprite with CORS and its integrity hash, parses it inertly, keeps only SVG-namespace content with no scripts, links or external URLs, and injects it once, so `<use href="#id">` works across origins. Icons need JavaScript in this mode and the CDN must send CORS headers; proxying `/icons/*` through your site stays the zero-JS option. Default builds are byte-identical to before.
  
  **Breaking (inject mode only):** the manifest becomes `version: 2` with `crossOrigin`, the sprite's `integrity` and a `loader` entry. It needs `@svgworm/react` 0.3, and an `Icon.astro` generated by an earlier `svgworm init` must be written again (delete it and run `svgworm init`) or edited to accept version 2. The JSON Schema gains `crossOrigin`, and svgworm now also removes stale `icons.loader.<hash>.js` files in `outDir`.
- 8fc1bb4: `svgworm init` now leaves a project that runs before you add any icon. When no source folder has an SVG, it adds a sample `icons/svgworm.svg` (CC0, icon name `svgworm`). Then it builds once, so `svgworm/icons.js` exists and the generated Icon component type-checks right away. Before this, `npm run dev` failed in the `predev` hook with `source folder not found` or `build/no-icons`. `init --json` gains a `build` key. If the first build fails, `init` keeps the files it wrote and exits 1 (or 2 for a setup problem).
- 0d9632a: License notices from the source files survive the build. An XML comment whose text starts with `@license` (Lucide, Tabler, svgo's own convention) or `!` (Font Awesome, minifiers) is written once per distinct text before the root element of the sprite or stack file that holds the icon, trimmed and sorted, so an ISC or MIT attribution travels with the copies. Every other comment is still dropped, including a `<!--! … -->` inside an icon, which svgo's preset used to keep in the symbol. The comment bytes are part of the content hash, so sprites built from files with such notices get a new name once.
- 2783172: The plain (non-TTY) output of `svgworm`, `svgworm check` and `svgworm watch` no longer prints one `icon <name> <color> <delivery>` line per icon. With a large set that was thousands of lines in every CI or `predev` run. It still lists the files written or removed, the warnings and errors, and the summary; `check` prints only its verdict when the output is up to date. Pass the new `--verbose` flag to get the per-icon lines back. `--json` output is unchanged and still includes every icon.
- 9af3e81: A `sources` entry can now be `{ "dir", "include", "exclude" }` as well as a folder path. `include` keeps only the files that match one of its globs and `exclude` drops matches after that, both on the `/`-separated path inside `dir` (`house.svg`, `arrows/*.svg`, `**/arrow-*.svg`, `{a,b}.svg`). This picks icons from a package such as `lucide-static` or `@tabler/icons` without copying files out of `node_modules`; names are unchanged (the path inside `dir`, so `house`). A source folder may be a symlink, as packages are in a pnpm `node_modules`. The JSON Schema and `ResolvedConfig.sources` (now `{ dir, include?, exclude? }` objects, a string normalizes to `{ dir }`) follow. Decided in ADR-0020.

### Patch Changes

- 5ef810a: Errors now say what to do next:
  
  - An unknown CLI flag suggests the closest known one (`unknown flag "--sources". Did you mean "--source"?`) instead of Node's positional-argument explanation.
  - A `name/collision` error ends with a fix: rename one of the files, or turn `flatten` off when the files sit in different folders.
  - The `Unknown icon` error thrown by the `@svgworm/react` component lists the closest icon names from the manifest.
  - An `svg/invalid-xml` message reads `line 2, column 0: …` instead of showing svgo's `<input>:2:0:` placeholder as the location.
- a1e0c35: The `Icon.astro` that `svgworm init` writes now keeps an object `style` on mask-delivered (mono stack) icons. Before, only a string `style` reached the rendered `<span>`; an object was silently dropped. The object is serialized the way React does it: camelCase keys become kebab-case, bare numbers get `px` except for unitless properties such as `opacity` and `z-index`, and custom properties (`--size`) pass through. Re-run `svgworm init` to regenerate the component, or copy the `userStyle` block from a fresh init.
- 69e342e: `svgworm init` ends its next steps with what to commit: `public/icons/` and `svgworm/` plus `svgworm check` in CI, or both folders in `.gitignore` with the scripts that run svgworm. `--component` (write the Icon wiring even when no framework dependency is found) now appears in `--help`, since an init hint already told users to pass it.
- b062c54: `svgworm init` fixes from dogfooding in monorepos and non-Next projects:
  
  - `--source` may point outside the project folder (`../../packages/icons/svg`), as `build` and `check` already allowed. The sample icon is never written into such a folder.
  - Run from a subfolder of a package (for example `src/`), `init` now stops with exit code 2 and names the folder that holds `package.json`, instead of writing a config there and skipping the component.
  - A framework chosen at the interactive prompt is reported as `(prompt)`, and `frameworkSource` in `--json` is `"prompt"`, not `"flag"`.
  - The Astro `base` hint says to set `publicPath` in `svgworm.config.json`, because `init` never edits an existing config.
  - The public-path prompt mentions the Next `basePath` only when `next` is a dependency (and the Astro `base` for Astro). The React next step says "Server Component" only for Next.js; Vite and plain React get "component".
- 0850ffc: `svgworm init` now rejects a `--config`, `--source`, `--out-dir`, `--module-dir` or `--component-file` path with spaces or shell characters (`$ & | ; < > ( ) * ? # ! ~`), as it already did for quotes. Those paths are written unquoted into the `package.json` scripts and the printed commands, so `init --config "my icons.json"` used to produce a script that failed with `unknown command "icons.json"`.
- b7419c8: A failure inside svgworm's own per-icon pipeline is no longer reported as `svg/invalid-xml` against the icon being processed. It now surfaces as `unexpected failure: …` with exit code 1, so a svgworm bug does not look like a broken SVG. An svgo error on the input itself (for example CSS it cannot parse) still comes back as an `svg/invalid-xml` diagnostic on that file, now prefixed with `svgo could not process the file:`.
- 7791a5b: `svgworm` with no `svgworm.config.json` and no `--source` now says what to do (run `svgworm init` or pass `--source <dir>`) instead of showing the validation issue for a missing `sources` field. When a config exists in a parent folder, the message names it, so running from a subdirectory of a project is no longer a puzzle. Exit code 2 is unchanged.
- ba850e9: Build-time validation now also rejects HTML elements an SVG can carry in another namespace (`base`, `meta`, `link`, `img`, `form`, `input`, `frame` and similar: `svg/forbidden-element`), a `srcdoc` attribute, and `src`, `data`, `action`, `formaction` or `poster` attributes that point outside the file (`svg/external-reference`). No icon set we test uses them; they could load documents or rewrite page URLs once a sprite is injected (security review of ADR-0027).
- 1e9c778: `svgworm init` now works with Yarn 2+ (Berry, including Plug'n'Play), which never runs `predev` or `prebuild`. Before, the sprite was silently never built. When it finds Yarn 2+ (a `packageManager` of `yarn@2` or later, a `.yarnrc.yml`, or a Berry `yarn.lock`, also at a workspace root), init prefixes the `dev` and `build` scripts with `svgworm &&` instead. It leaves a script that is missing or that uses `||`, `;` or `&` untouched and prints a warning naming it. `init --json` reports that warning as `warning` on the `package.json` action.

## 0.1.0

### Minor Changes

- 2726847: Add `svgworm check` and `svgworm watch`. `check` compiles the icons, compares the result with the files on disk without writing, lists each missing, changed or stale file plus the icon names added or removed, and exits `1` when the committed output is stale (`0` when up to date). `watch` builds once and rebuilds everything after each change in a source folder, until Ctrl+C. Both take the same flags as `build`, including `--json`. The programmatic API gains `check`, `watch` and `compileFromDisk`.
- c68a13f: Color classification now sees markers, CSS variable paints and SMIL color animations (ADR-0013). Marker content counts toward an icon's colors and is recolored with the icon when it is mono, so a mono line with a differently colored arrowhead is multicolor instead of being half recolored. A `var(--…)` paint or an `<animate>`/`<set>` on a paint property makes the icon multicolor and it is never rewritten, keeping the author's theming or animation intact. Forcing `mono` on such an icon is an error that names the reason.
- 0da4021: Publish `svgworm.schema.json`, the JSON Schema of `svgworm.config.json`, and export it as `svgworm/schema.json`. Add package READMEs and npm keywords. `pnpm schema:generate` regenerates the file, and a test fails when it is stale.
- d3be39d: `svgworm watch` is incremental: only icons whose content changed are re-optimized on a rebuild (about 10 ms for 1,000 unchanged icons), through an in-memory per-icon transform cache (ADR-0015). The plain reporter marks reused icons with `(cached)`, and the `icon` event gains `fromCache`. The programmatic API gains `createTransformCache()` and a `cache` option on `compile`, `build` and `compileFromDisk`. One-off builds and `check` never use a cache.
- b0c6239: Add `svgworm init`. On an interactive terminal it asks for the icon folder, the public path and what to write; otherwise flags answer everything (`--source`, `--public-path`, `--component-file`, `--no-component`, `--no-scripts`, `--agents-md`, `--yes`, `--json`). It writes `svgworm.config.json` with its `$schema`, adds `predev` and `prebuild` scripts that run `svgworm` (chaining before existing scripts), creates the `createIcon` wiring when `react` or `next` is a dependency, and can append a marked svgworm section to `AGENTS.md`. It never overwrites a file whose content differs, so re-running it is idempotent, and it prints the install and next-step commands for the detected package manager.
- eebb113: First working build: `svgworm` turns a folder of SVG files into a content-hashed sprite, a stack file for icons with `url(#...)` references, a manifest module, and types, following output contract v0.1. It adds the CLI (`--source`, `--out-dir`, `--public-path`, `--module-dir`, `--flatten`, `--json`), per-icon color classification, collision and invalid-SVG errors that write nothing, and stale-sprite cleanup. Exit codes are `0` built, `1` invalid input or I/O failure, `2` usage or config error. `@svgworm/react` is versioned together with `svgworm` and has no changes yet.

### Patch Changes

- a9aff9d: Hardening from the pre-release code and security review.
  
  - Validation rejects `<script>` and other embedding elements under any namespace prefix (`<x:script>` was accepted and reached the sprite), `<foreignObject>`, CSS-escaped `url()` references, `javascript:` with embedded whitespace, SMIL that retargets `href` or event handlers, and `data:` hrefs that are not raster images.
  - Output files are written through a temporary file and renamed into place: a reader never sees a half-written module, and a symlink at the output path is replaced instead of followed. Files whose bytes did not change are left untouched, so `svgworm watch` next to a dev server no longer triggers reloads for no-op saves.
  - `svgworm watch` attaches its watchers before the first build (edits during it are no longer lost), reports a failed watcher instead of going quiet, never rebuilds after Ctrl+C, and waits for a build in flight before exiting. Ctrl+C ends `build` and `check` at once again.
  - `svgworm init` refuses paths outside the project or containing quotes, backticks or line breaks, validates the config it is about to write with the same rules as `build`, keeps a custom `--config` in the scripts it adds, preserves `package.json` line endings and indentation after a blank line, keeps several `--source` folders in interactive mode, and never overwrites a file that appeared or changed while its prompts were open.
  - `svgworm check` reports read errors other than a missing file instead of listing the file as missing.
  - `@svgworm/react` forwards `id`, `data-*`, `aria-*` and other HTML attributes to the `img` and `mask` deliveries, and treats prototype keys such as `constructor` as unknown icons.
