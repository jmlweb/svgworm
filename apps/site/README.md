# svgworm site

The landing page and the user docs, built with Astro and deployed to Cloudflare Workers static assets ([ADR-0016](../../docs/adr/0016-project-site-astro-on-cloudflare-workers.md)). The docs are Markdown files in `src/content/docs/` ([ADR-0018](../../docs/adr/0018-user-docs-on-the-site-rendered-from-docs.md)). It is also a demo: every icon comes from a hashed svgworm sprite rendered by the `Icon.astro` that `svgworm init` generates (ADR-0017), no icon needs JavaScript (the only scripts are small inline ones: copy buttons, the paused worm, and the WebMCP tools), and `/icons/*` is served `immutable`.

```bash
# from the repo root
pnpm install && pnpm build        # build svgworm and @svgworm/react
pnpm site:build                   # svgworm, then astro build into apps/site/dist
pnpm site:check                   # svgworm check, build, then the output check
pnpm --filter svgworm-site dev    # svgworm, then astro dev
```

| File                          | Role                                                                                                                                                                                                                          |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/pages/index.astro`       | The landing page: `Landing` inside the `Base` layout                                                                                                                                                                           |
| `src/layouts/Base.astro`      | Head (title, description, canonical, Open Graph), header, footer and `WebMcp`, shared by every page                                                                                                                                      |
| `src/content/docs/*.md`       | The user docs, one page each at `/docs/<name>`. Frontmatter `title`, `description` and `order` are required (`src/content.config.ts`). Callouts are `<aside class="alert alert-tip">` blocks (`note`, `tip`, `important`, `warning`, `caution`) |
| `src/pages/docs/`             | `/docs` (index) and `/docs/<name>` (one page per doc)                                                                                                                                                                          |
| `src/pages/llms.txt.ts`, `llms-full.txt.ts` | `/llms.txt` serves the repo-root `llms.txt` as is; `/llms-full.txt` adds the full text of every doc page                                                                                                         |
| `src/components/Landing.astro` | The page content, with `Install.astro` and `Soil.astro`                                                                                                                                                                       |
| `src/components/WebMcp.astro`, `src/lib/webmcp.ts` | [WebMCP](https://webmachinelearning.github.io/webmcp/) tools for agents in the browser: `list_docs`, `get_doc`, `search_docs` (doc bodies from `/llms-full.txt`) and `open_doc`. Nothing is registered without the API |
| `src/components/Icon.astro`   | Generated by `svgworm init --framework astro`; delete it and re-run `init` to refresh it                                                                                                                                       |
| `tests/`                      | `icon-conformance.test.ts` renders `Icon.astro` and `createIcon` from a fixture manifest and compares the markup; `webmcp.test.ts`, `api-catalog.test.ts` and `robots.test.ts` cover the agent discovery surface (`pnpm test`)                                                                                                |
| `icons/`                      | Lucide SVGs (ISC, mono) and Fluent Emoji Flat SVGs in `icons/emoji/` (MIT, multicolor), see `LICENSES.md`                                                                                                                     |
| `public/icons/`, `svgworm/`   | Generated output, committed so `svgworm check` fails CI when an icon changes without a rebuild                                                                                                                                |
| `public/_headers`             | `Cache-Control: public, max-age=31536000, immutable` for `/icons/*`, `/fonts/*` and `/_astro/*`; the RFC 9727 API catalog type for `/.well-known/api-catalog`; the RFC 8288 `Link` header on `/`                                                                                                                                            |
| `og/og.html`, `public/og.png` | The link preview image (1200×630) and its source. After changing `og.html`, re-render it from `apps/site` with any Chrome: `chrome --headless --hide-scrollbars --window-size=1200,630 --screenshot=public/og.png og/og.html` |
| `scripts/check-output.mjs`    | Fails on an unknown or unused sprite icon, a missing cache rule, a doc without a page, a page without a title, description, canonical URL or sitemap entry, or a missing `llms.txt` or `llms-full.txt`                      |
| `wrangler.jsonc`              | The assets-only Worker `svgworm`, with preview URLs on                                                                                                                                                                        |

There is no `@astrojs/react`: Astro always emits a renderer's client entrypoint into `dist/`, even when no component hydrates. React, `react-dom` and `@svgworm/react` are dev dependencies for the conformance test only; nothing from them reaches `dist/`.

## Deploys

`.github/workflows/site.yml` runs `pnpm site:check`, then `wrangler deploy` on every push to `main`, or `wrangler versions upload --preview-alias pr-<number>` on a same-repo PR (the URL is in the job summary). Fork PRs skip the job. It needs the repo secrets `CLOUDFLARE_API_TOKEN` (a token with the "Edit Cloudflare Workers" template) and `CLOUDFLARE_ACCOUNT_ID`. Preview uploads need the Worker to exist, so the first deploy must come from `main` (or `pnpm --filter svgworm-site cf:deploy` by hand; `pnpm deploy` is a built-in pnpm command, hence the prefix).
