# 0032. Markdown for agents through a small site Worker

- **Status:** accepted
- **Date:** 2026-10-16
- **Task:** none (agent-readiness fixes from isitagentready.com, requested by the maintainer)
- **Resolves:** none. Supersedes only the "assets-only Worker, no script" part of [ADR-0016](0016-project-site-astro-on-cloudflare-workers.md). Astro, the host, the layout, the deploys and the checks of ADR-0016 stay in force, and ADR-0016 itself is not edited.

## Context

Agents that fetch svgworm.com get HTML with navigation, a hero and a footer around the content they want. The agent-readiness scan (`checks.contentAccessibility.markdownNegotiation`) asks for content negotiation: a request with `Accept: text/markdown` gets a markdown representation, and browsers still get HTML by default.

The site is an assets-only Worker (ADR-0016). Static assets alone cannot choose a response by the `Accept` header, and `_headers` cannot rewrite a path.

## Options considered

1. **Cloudflare Markdown for Agents** (the zone setting that converts HTML at the edge): no code, but it needs a Pro, Business or Enterprise plan ([docs](https://developers.cloudflare.com/fundamentals/reference/markdown-for-agents/)). The zone is on the Free plan. It would also convert the header, the footer and the landing page's demo markup.
2. **A URL Rewrite Rule in the dashboard** that sends `Accept: text/markdown` requests to prebuilt `.md` files: no script, but the rule lives outside the repo, cannot be reviewed or tested in a PR, and needs a second rule for `Vary: Accept`.
3. **A small Worker script that runs first only on the pages**, serving prebuilt `.md` files when the request prefers markdown: versioned and tested with the site, and it works on the Free plan. It adds a script to the site and Worker invocations for page requests.

## Decision

Option 3.

- The build writes one markdown file per page from the same sources the pages use: `/index.md` from the repo-root `llms.txt` (the summary agents already read), `/docs.md` as the docs index, and `/docs/<slug>.md` from each doc's Markdown source. No HTML is converted.
- `apps/site/worker/index.ts` runs first only for `/`, `/docs` and `/docs/*` (`assets.run_worker_first`); every other path stays asset-first with no invocation. For a `GET` or `HEAD` whose `Accept` gives `text/markdown` a q-value above zero and at least that of `text/html`, it returns the page's `.md` asset as `text/markdown; charset=utf-8`. Otherwise it returns the asset unchanged. Both answers carry `Vary: Accept`.
- The Worker reads assets through the `ASSETS` binding only. It has no dependencies and no state, and the site still ships the same HTML.

## Evidence

- The Cloudflare docs list Markdown for Agents for Pro, Business and Enterprise plans only, and the maintainer confirmed on 2026-10-16 that the zone has no Pro plan.
- `run_worker_first` accepts an array of route patterns, and `env.ASSETS.fetch` accepts a `Request`, a `URL` or a string ([static assets binding](https://developers.cloudflare.com/workers/static-assets/binding/)).
- The `_headers` docs say custom headers are not applied to responses generated by Worker code ([headers](https://developers.cloudflare.com/workers/static-assets/headers/)). A `wrangler dev` prototype (2026-10-16) that returned `env.ASSETS.fetch(request)` for `/` and `/docs/cli/` still carried the `_headers` rules: the CSP with the build-time script hashes, HSTS, and the homepage `Link` header. The Worker therefore returns asset responses with headers added, never a new response built from scratch. A production check after the first deploy confirms the same.

## Consequences

- Agents get clean markdown at the page URL they already have, and browsers see no change.
- Page requests to `/` and `/docs/*` count against the Workers request quota (100,000 a day on the Free plan); sprites, fonts, `/_astro/*`, `llms.txt` and the well-known files do not.
- A new page needs a `.md` source next to it, or it falls back to HTML. `scripts/check-output.mjs` fails the build when a doc has no `.md` file.
- If the Free plan later gains Markdown for Agents, or the zone moves to Pro, the Worker can be removed in favour of option 1 with a superseding ADR.
